# PRD: Главная страница (лендинг)

**Дата**: 2026-09-10

**Статус**: Draft

## Цель

Публичная главная страница `apps/web` по маршруту `/` — лендинг OpsPilot:
объясняет, что делает сервис, и даёт вход в личный кабинет. Итерация — только
вёрстка: статичный контент, без запросов к API и без реальной авторизации.

## Пользовательский сценарий

- Пользователь открывает `/` -> видит лендинг: шапка с кнопкой «Войти», hero,
  блок функционала, блок «Как это работает», футер.
- Пользователь кликает «Войти» (в шапке или в hero) -> `RouterLink` ведёт на
  `/login` -> рендерится view-заглушка `LoginView`.
- Пользователь сужает окно до ширины телефона (~375px) -> секции
  перестраиваются в одну колонку, горизонтального скролла нет.

## В скоупе

- Новый компонент `apps/web/src/views/LandingView.vue`, привязан к маршруту `/`.
- Секции лендинга (сверху вниз):
  - **Шапка** (`<header>`, sticky сверху): логотип-текст «OpsPilot» слева,
    `<Button>` «Войти» (`RouterLink` на `/login`) справа.
  - **Hero**: заголовок, подзаголовок (1–2 предложения про OpsPilot), основная
    `<Button>` «Войти в личный кабинет» (на `/login`).
  - **Функционал** (`features`): сетка карточек (≥4), каждая — иконка
    `@lucide/vue` + заголовок + описание. Темы карточек:
    анализ тикетов Claude-агентом; агент **предлагает** действия, не выполняет;
    approve/reject решает человек; доступ к данным только через MCP-инструменты
    и Internal API.
  - **Как это работает** (`how-it-works`): 4 пронумерованных шага
    `тикет -> RabbitMQ -> агент (fake|claude) -> предложение -> человек
    одобряет/отклоняет`.
  - **Футер** (`<footer>`): текст `© 2026 OpsPilot` и ссылки-заглушки
    (`<a href="#">`), без реальных адресов.
- Разметка кнопок — через вендорный `@/components/ui/button`.
- Стили — utility-классы Tailwind v4; собственный `<style>` в компоненте
  минимальный или отсутствует.
- Маршрут `/login` + минимальная `apps/web/src/views/LoginView.vue`
  (заголовок-заглушка «Вход», текст «Скоро»), зарегистрирован в
  `src/router/index.ts`.
- Vitest-спеки: `LandingView.spec.ts` (секции рендерятся, `RouterLink` на
  `/login` присутствует) и правка/замена существующего `HomeView.spec.ts`.
- Обновлены `apps/web/CLAUDE.md` (структура `views/`), `docs/STATUS.md`.

## Не в скоупе

- Реальная авторизация, формы логина, токены, guard-ы маршрутов.
- Запросы к API, Pinia-стор для лендинга, индикатор здоровья бэкенда на `/`
  (существующий `useHealthStore` остаётся в коде, но на `/` не рендерится).
- Тёмная тема и переключатель темы (токены `.dark` в `main.css` не трогаем).
- i18n / мультиязычность — текст только на русском, зашит в шаблон.
- Реальные тексты бренда, логотип-изображение, favicon, картинки hero,
  анимации, SEO-мета, аналитика.
- Новые npm-зависимости.

## Технические ограничения

- Vue 3 Composition API, `<script setup lang="ts">`, TypeScript strict — без
  `any`, без Options API, без `defineComponent`.
- Только уже установленные библиотеки: Tailwind CSS v4, shadcn-vue
  (`reka-ui`, `cva`, `clsx`, `tailwind-merge`), иконки `@lucide/vue`, `vue-router`.
  Компоненты shadcn-vue добавляются только через
  `docker compose exec web npx shadcn-vue@latest add <name>` (нужна сеть; файлы
  контейнер пишет от root — потом `chown 1000:1000`).
- Все команды — в контейнере `web` (`docker compose exec web npm run …`).
- `HomeView.vue` и его спека сейчас отвечают за `/`; замена маршрута ломает
  `HomeView.spec.ts` — спека должна быть обновлена или удалена в том же
  изменении.
- Каждое изменение кода — с правкой доков (root/модульные `CLAUDE.md`,
  `README.md`, `docs/`), иначе Stop-hook ругается.
- TDD: сначала падающая Vitest-спека, потом компонент.

- [ ] `docker compose exec web npm run test` -> зелёный; спеки
      `LandingView.spec.ts` и `LoginView` покрыты, `HomeView.spec.ts`
      обновлён/удалён, счётчик в `docs/STATUS.md` совпадает.
- [ ] `docker compose exec web npm run lint` -> exit 0 (oxlint + eslint).
- [ ] `docker compose exec web npm run type-check` -> exit 0.
- [ ] `docker compose exec web npm run build` -> exit 0.
- [ ] `curl -s http://localhost:5173/` -> HTTP 200; в DOM присутствуют секции
      `header`, hero-заголовок, `features`, `how-it-works`, `footer`.
- [ ] На `/` видна кнопка «Войти» со ссылкой на `/login`; переход на `/login`
      рендерит `LoginView` без ошибок в консоли.
- [ ] Блок функционала содержит ≥4 карточки, блок «Как это работает» — ровно 4
      пронумерованных шага.
- [ ] При ширине ~375px `document.documentElement.scrollWidth ===
      clientWidth` (нет горизонтального скролла); секции в одну колонку.
- [ ] На странице нет сетевых запросов (вкладка Network пуста после загрузки).
- [ ] `apps/web/CLAUDE.md` и `docs/STATUS.md` отражают новые `views/` и маршрут
      `/login`.
